# Talos Labs rules catalog (macOS)

Catalog version `0.2.0`. 31 rules. Every rule has a stable id, a reader-facing title, a fail title, a severity, a category, a CIS reference where one exists, the state fields it reads, a pass condition, a fix, and (from v0.2) an in-app fix mode.

## Benchmark edition

`cisEdition` is pinned to **CIS Apple macOS 26 Tahoe Benchmark v1.0.0**. Every number in the CIS column refers to that edition. `docs/CIS-MAP.md` is the source of truth for the numbers; it was verified against the NIST mSCP `tahoe` branch on 2026-10-15. The Sequoia (macOS 15) edition uses the same numbers for every control the catalog cites. Sonoma and earlier number some sections differently (Gatekeeper 2.6.4, Lock Screen 2.10.x, Users & Groups 2.12.x); do not use those.

## Conventions

- `title` states what is checked ("Your disk is encrypted"). It is a full statement with a verb, never a noun phrase, because the `unknown` headline is "Couldn't check whether " plus the title with an ordinary opening word lower-cased; acronyms and names such as "SSH keys" and "Remote Login" keep their capital. A catalog test asserts every title carries a finite verb. `failTitle` states the problem ("Your disk is not encrypted") and is the finding's `headline` on `fail` and `review`.
- The app hides `fix.commands` unless Developer mode is on, so a fix that has a Settings path never has a step that says "run the command shown" or names Terminal, and `fix.verify` and `fix.summary` never name Terminal or a command-line tool. A step never spells out a program that `fix.commands` already carries; the step refers to the command by position or not at all. Catalog tests assert all of these. A fix with no Settings path may still need Terminal.
- `S.` means `state.sections.`. A rule whose `requires` section is unavailable returns `unknown` with that section's reason before `evaluate` runs. A rule may also return `unknown` itself: with a nested section's `UnavailableReason` (028 forwards `BrowserReport.extensions.reason`, which the `requires` check cannot see) or with `indeterminate` when the data is present but inconclusive. `rule_error` is set by the engine only.
- Rules that measure age (027) compare against `state.collectedAt`, not `ctx.now`, so a recheck on a held state gives the same answer.
- `n/a` means `not_applicable`.
- `Tri` fields: `"unset"` means the OS default. "not false" passes for `true` and `"unset"`.
- Commands in `fix.commands` are display text with a copy button; the app never executes that text. The `in-app fix` column says what the app can do itself in v0.2 (`docs/DESIGN-V02.md` section 5): `apply` means the Rust `FIX_CATALOG` holds a fixed command line for this rule, run only after an in-app confirmation and followed by an automatic recheck of the listed section; `settings link` means a one-click deep link into the named System Settings pane, after which the app polls the listed section while the user is away so the finding updates itself; `none` means steps only, with a Finder reveal or a watcher where noted. The column shows the exact command or pane; `(admin)` runs through macOS's own administrator dialog, `(user)` runs directly. `fix.commands` is a list in display order. `(admin)` is rendered with a `sudo` prefix. `(interactive)` means the command prompts in Terminal. A command's `{path}` placeholder is filled from the path-kind evidence entries of the same finding whose key equals the command's `appliesTo`, one rendered command per entry, never from model output. A command with `appliesTo: null` has no placeholder and renders once.
- Settings paths are macOS 26/27 System Settings labels.
- Effort: `two_minutes`, `ten_minutes`, `half_hour`. Side effects: `none`, `restart`, `reauth`, `workflow`.

## Rules that apply to other platforms

Every rule above declares `os: ["macos"]`. On another host the engine returns `not_applicable` without calling `evaluate`. Windows and Linux rules get their own ids (`TL-WIN-`, `TL-LNX-`) and read the same `SystemState` shape.
