# Talos Labs watch design: a small window in the menu bar that keeps checking

v0.3 made the app drive when it is opened. DESIGN-AI connected the person's own AI. This document adds the piece the owner asked for next: the app lives in the menu bar as a small window, re-reads the Mac's settings on a timer, notices when something changed since the last check, and, when the change looks like what a malware infection leaves behind, walks the person through what published incident-response playbooks say to do, step by step, naming the playbook and the step each time.

This document extends `docs/DESIGN-V03.md`, `docs/DESIGN-AI.md`, `docs/DESIGN-MINERAL.md` and `docs/DESIGN-WARMTH.md`. The security model in `docs/SECURITY-MODEL.md` keeps every boundary: code collects and judges, the model only explains and suggests, it never runs anything and never receives machine text (paths, process names, hostnames, labels, addresses); anything that changes the Mac is a fixed catalogue entry run after a confirmation, admin ones through macOS's own dialog; no shell; no root; nothing read from file contents beyond the existing narrow exceptions and the two new ones declared in section 2; no password field ever drawn by the app. Two standing constraints are overridden on purpose (below). Everything else in v0.3 holds: no nagging, one primary per guided screen, plain British English, the banned-word list in `apps/desktop/src/guided/copy.ts`. Facts about the tree and the Mac were checked on 2026-10-17 on macOS 27.0 (arm64, admin user, no sudo); facts about Tauri were checked against tauri 2.12.4 and the 2.x plugin lines of the same date; playbook step numbers were read from the source PDFs on 2026-10-17 (section 4 says which).

The owner's brief, verbatim: "have the app run in the top bar of the mac as a smaller window that keeps regularly checking for threats, i.e., checks the computer specs and runs an agent to make sure we are not missing anything and suggests proactive actions when something seems fishy (look at famous cyber strategies in case there is a malware, e.g., cut the internet, isolate threat etc.)". The owner then asked to overemphasise the last part: every suggested action must come from a well-known, published incident-response strategy for a suspected malware infection, not from the app or the model, and each action must be mapped to the step of the playbook it comes from, so the person sees what experts would do and why. Section 4 is that map. No action in this document is suggested without a source and a step.

**Why the top bar window was not built before this document.** On 2026-10-17, before this build, nothing of it existed in the repo. `apps/desktop/src-tauri/Cargo.toml:35` had `tauri = { version = "2", features = [] }`, so Tauri's `tray-icon` feature was not compiled in; `apps/desktop/src-tauri/src/lib.rs` built one window and called `.run()` with no run-event callback, so closing the main window ended the process; `apps/desktop/src-tauri/tauri.conf.json` declared one 1100 x 760 window with `transparent: false`, and `capabilities/default.json` granted only `main`. A grep for tray, TrayIcon, ActivationPolicy, autostart and notification over `apps/desktop/src`, `apps/desktop/src-tauri/src` and `docs` found nothing. It was absent by decision, written down in five places: `docs/DESIGN-V03.md:472` ("No notifications, no menu bar agent, no background scans. The app speaks only when it is opened."), `docs/DESIGN-V03.md:733` (section 9, out of scope: "Scanning while the app is closed, a menu bar agent, notifications, scheduled scans"), `docs/SECURITY-MODEL.md:249` ("Scan, fix or watch while the app is closed"), `readme.md:3` and `:9` ("no background agent"), and the older `docs/DESIGN.md:461` and `docs/DESIGN-V02.md:1064`. The design kit's website repeated it ("No background monitoring.", "Does the app run in the background? No."). The owner's brief came after those documents were written, and a feature that contradicts the written design needs a design that re-decides it before any code. This document was that step. Two platform facts also gate a working build and are not the project's to change: ad-hoc signed dev builds get an empty TCP socket table (`docs/notes/socket-table-signing.md`), so the network signals only exist in a Developer ID build; and macOS delivers notifications only for a bundled app, so a dev build's banners arrive under Terminal's name (section 5). The lines quoted above have since been replaced with the wording given under "Decisions taken" below, and the built state (`tray-icon` on, `src/tray.rs`, the `watch` window, `capabilities/watch.json`, the run-event callback and the notification, autostart and single-instance plugins in `lib.rs`) is recorded in section 11.

Decisions taken where the brief left room:

- **The "agent" is Rust, not the model.** Under the standing rule, code collects and judges. So "runs an agent to make sure we are not missing anything" means: a Rust loop runs the fixed read-only probes on a timer, compares each with its own stored baseline, and a pure function rates the result. The model, when one is connected, is a one-shot judge per cycle: it receives a derived document (ids, booleans, counts, same/changed flags), returns a rating clamped between a floor and a ceiling that code computed, and may name up to three probe ids to re-read next and up to three action ids from the playbook table. The probes it may name are a closed subset that read metadata only (listings, `stat`, the existing binaries with fixed arguments); the two Rust-only probes (`probe.persistence_signatures`, which runs `codesign` on a binary, and `probe.ssh_keys`, which is `stat` only) are never model-chosen. It never names a program, a path, a port or an argument, and it never runs a tool loop. With AI off the same fixed rules produce the same screens.
- **Rust owns the whole cycle.** The timer, the probes, the document, the rating, the model call, the validator and the baseline all live in `apps/desktop/src-tauri/src/watch/`. The webview reads state and never takes part in a cycle, so the watch works with no window open. The TypeScript mirrors in `packages/core` exist for the demo adapter, the fishy flow and the tests, and a fixture parity test pins them to the Rust versions. The ChatGPT request for the watch task is therefore made from Rust (`ureq`, already a dependency), to the same `api.openai.com` endpoint the webview uses today; it is a new caller, not a new destination, and section 7 says so.
- **Two constraints are overridden on purpose, and narrowly.** DESIGN-V03 section 4's "No notifications, no menu bar agent, no background scans; the app speaks only when it is opened" and the readme's "no background agent" are replaced by the exact wording below. The override is this and no more: the watch re-reads settings on a timer, shows its state in a menu bar icon, and sends one notification on a transition into "act now", once per item. It never scans files, never fixes anything on its own, never notifies about anything else (not the licence, not the AI, not a calm result), and the main window still speaks only when it is opened.
- **New wording for `docs/DESIGN-V03.md` section 4.** In "When it scans", replace "Never on focus or wake: a window left open for a week shows the same end screen until the app is reopened or "Check again" is pressed." with: "The main window never scans on focus or wake: a window left open for a week shows the same end screen until the app is reopened or "Check again" is pressed. The menu bar watch ticks on wake (`docs/DESIGN-WATCH.md`)." In "No nagging", replace the last two sentences, "No notifications, no menu bar agent, no background scans. The app speaks only when it is opened.", with: "The menu bar watch (`docs/DESIGN-WATCH.md`) is the one exception, decided on purpose: while it is on, the app re-reads settings on a timer, shows one of three states in the menu bar, and may notify once when something needs doing now. The main window still speaks only when it is opened, and the watch never fixes anything on its own." Section 9's first bullet, "Scanning while the app is closed, a menu bar agent, notifications, scheduled scans; "next time you open me" is literal.", becomes: "Scanning files, real-time protection, notifications for anything but the watch's "act now"; the menu bar watch re-reads settings only (`docs/DESIGN-WATCH.md`), and "next time you open me" is literal for the main window with the watch off."
- **New wording for `readme.md`.** Line 3: replace "There is no account, no server and no background agent." with "There is no account and no server. The only background work is the optional menu bar watch, which re-reads the same settings on a timer and can be switched off." Line 9: replace "The app speaks only when it is opened: no notifications, no menu bar agent, no background scans, no nagging." with "The main window speaks only when it is opened. The menu bar watch re-reads your settings on a timer you choose, shows a small icon, and tells you once when something needs doing now, never about anything else. It is not antivirus: it reads settings and start-up lists, never your files. See [docs/DESIGN-WATCH.md](docs/DESIGN-WATCH.md)."
- **New wording for `docs/SECURITY-MODEL.md`, "What the app never does".** Replace "Scan, fix or watch while the app is closed. No notifications, no menu bar agent, no scheduled scans." with "Change the Mac from the menu bar watch without the same confirmation and the same dialog as the main window. The watch re-reads settings on a timer and compares them with its own baseline; it never runs a fix on its own, never reads file contents beyond the two declared exceptions, and notifies only on a transition into 'act now', once per item." `docs/DESIGN.md:461` and `docs/DESIGN-V02.md:1064` get a one-line note each pointing here. The further SECURITY-MODEL changes are listed in section 7.
- **Welcome tells the person before it happens.** Welcome's body gains one sentence before the first check-up: "I'll also keep an eye on your settings from the menu bar. You can switch that off in Settings." (1.21 syllables per word.) The watch is on by default because the brief says "have the app run in the top bar". Closing the main window leaves the menu bar item in place. Start at login is off by default because it writes a LaunchAgent to `~/Library/LaunchAgents`, which is a persistence item the app itself reports under rule 023; it is offered once in the small window's first state and in Settings, never nagged.
- **Honest about what it is.** It is not antivirus and says so in the app, the readme and the website. It reads settings and start-up lists, compares them with the last check, and cannot see what a program does. macOS's own XProtect does the file part. Any area the build cannot read is shown as "I couldn't check", never as calm.
- **Changes the person made on purpose are asked about before anything else.** Turning on Screen Sharing for a relative or adding a family account looks the same as an attacker doing it. So the flips a person makes in System Settings (firewall off, remote access on, a guest share, a new administrator, automatic login, backups off) are "something to look at" plus one question, "Did you just change this?", and become "act now" only when the person answers "No, I didn't" or a second signal corroborates. The flips that need Recovery or root (SIP, Gatekeeper, XProtect) stand alone. No notification goes out for a gated flip until the person has answered or a second signal has appeared.
- **The first cycle rates nothing.** It writes the baseline. A change is only ever counted against a baseline that already exists, so an old script under `~/.local/bin` cannot trigger an alarm on day one.
- **Playbook sources, named and dated.** NIST SP 800-61 Rev. 3 (April 2025) is the current revision and is cited for the outcome names (RS.MI-01 contain, RS.MI-02 eradicate, RC.RP recover, RS.AN-07 evidence, RS.CO-03 report, ID.IM lessons learned). It has almost no single-machine wording, so Rev. 2 (2012, superseded 2025-04-03) is cited for the concrete sentences in its sections 3.3.1, 3.3.2, 3.3.4 and 3.4.1, and every on-screen line that quotes it says "2012 edition". The CISA #StopRansomware Guide v3.0 (October 2023) gives the only numbered, ordered checklist; its step numbers were read from the PDF text on 2026-10-17. SANS's Incident Handler's Handbook (Kral, 2012) gives the PICERL phases. CISA's home-user tips (2019; CMU/US-CERT 2008) give the single-computer version. The NCSC's "Mitigating malware and ransomware attacks" gives the UK line on ransom. Apple's Platform Security Guide, the Apple Account and Personal Safety pages and the Lockdown Mode article give the Mac-specific steps; those were read through fetch summaries and must be re-read from the raw page before release.
- **No US agency is hard-coded.** CISA's reporting step names the FBI and IC3. The app says "the police or your country's cyber security centre" and opens no URL for it in this version.
- **The containment action is a choice with its trade-off, never automatic.** NIST SP 800-61r2 3.3.1 warns that disconnecting can itself trigger damage. The disconnect screen says "This may not stop everything" and the person presses the button. Nothing in the watch ever runs a catalogue entry without the person's confirmation.
- **Source links open from one place only.** Each playbook row carries a URL. It opens only from the Details disclosure of a source row, from Rust, keyed by action id. SECURITY-MODEL's Network list gains that one row (section 7). Nothing opens on its own.
- **The unified log and `periodic` are dropped.** The log is readable by admin accounts only (`/var/db/diagnostics` is `root:admin 750`), so on the hardened account rule 014 recommends the signal vanishes; and the documented XProtect detection predicate returned nothing on macOS 27 in 14 days. `/etc/periodic` and `/usr/sbin/periodic` do not exist on macOS 27. Neither is promised.

## 1. What the watch is and is not

**What it is.** A menu bar item and a 320 px window, backed by a Rust timer. Every interval (default one hour) Rust runs a fixed list of read-only probes (section 2), reduces each to booleans, counts, versions and a keyed digest, compares with the stored baseline, and lets `rate_watch` turn the changes into one of three states: calm, something to look at, act now. The icon shows the state. The window shows the last-check time, one headline, one primary. "Act now" may send one notification. The "something seems fishy" flow (section 6) opens in the main window and is a guided set of screens whose every action carries its playbook and step.

**What it is not, and how the app says it.** Not antivirus, not EDR, no real-time protection, no file scanning, no signatures, no network traffic inspection, no EndpointSecurity (the project has no entitlement and must not assume one), no process inspection, no ability to tell good software from bad, no ability to remove anything. The sentence, used in Welcome's "What do you look at?" disclosure, under the Watch section in Settings and on the website: "I'm not antivirus. I read your Mac's settings and the list of programs that start on their own, then tell you when something changed. I never read your files. macOS's own virus checks do that part." (1.33.)

**Honest claims the UI may make.** "Checked 12 minutes ago." "Nothing changed since the last check." "A new program started running on its own." "A built-in safety guard was switched off." "I couldn't check 3 areas." The UI may never say "protected", "secure", "no malware", "clean" or "safe", and it never names who did something: the app knows a value flipped, not who flipped it. A calm icon means "nothing I read changed since the last check", and the tooltip says exactly that.

**What a credible case looks like.** One signal is rarely enough; installers and updaters touch the same places. "Act now" needs a protection that only Recovery or root can switch off turning off, or two corroborating signals within 24 h, or a gated flip the person says they did not make. A single new background program, signed or not, is "something to look at". Section 3 gives the exact rules.

**Dev-build truth.** Under `pnpm desktop` the socket table is empty, so listener, remote access and file sharing signals read "I couldn't check" on every tick. Notifications in a dev build are delivered under Terminal's name (section 5). The whole feature can only be seen end to end on a Developer ID build (section 9).

## 2. Signals and probes

A probe is one read-only collector run. A signal is one derived value from a probe. The probe catalogue is a compiled-in table in Rust (`apps/desktop/src-tauri/src/watch/probes.rs`), keyed by probe id; the webview and the model name a probe id and nothing else. Every binary is in `exec::Bin` with the existing rules (`env_clear`, no shell, 5 s timeout, 1 MiB output cap). New `exec::Bin` entries: `Nvram`, `Xprotect`, `Profiles`, `Systemextensionsctl`, `Kmutil`, `Networksetup` (get commands only), `Scutil`, `Pmset`, `Crontab`, `Atq`, `Last`. The last three print user names and hostnames; each is reduced to a count inside its probe function and the text never leaves it. Timed on this Mac: the cheap sweep below runs in about 0.6 s.

**Two classes of probe.** `MODEL_PROBES` is the closed subset the model may name: every probe in it reads listings, `stat`, `defaults read`, the existing binaries with fixed arguments, and the launchd plists under the existing declared exception (`probe.persistence` reads label, program path and `RunAtLoad` as the collector does); none reads any other file bytes. `RUST_PROBES` are chosen by the loop and never by the model: `probe.persistence_signatures` (runs `codesign` on a binary) and `probe.ssh_keys` (now `stat`-only, see row 12; the existing `scan_keys` 4 KiB header read is never called from the watch). The webview cannot name a probe at all.

**Change detection without machine text.** Rust keeps, per signal, a baseline that is a boolean, a count, a numeric version, or an HMAC-SHA-256 digest of the sorted listing under a per-install key (section 7). A change is `baseline != current`. The document the model or the webview sees carries only `same`, `changed`, `first_seen`, `appeared` or `cleared`, plus the boolean or count where the value itself is safe. Paths, labels, process names, team ids, addresses and URLs never leave the Rust probe.

**Cheap sweep (every tick).** `probe.platform_integrity`, `probe.firewall`, `probe.malware_protection`, `probe.remote_access`, `probe.file_sharing`, `probe.listeners`, `probe.accounts`, `probe.persistence`, `probe.network_config`, `probe.hosts`, `probe.profiles`, `probe.system_extensions`, `probe.backup`, `probe.lockdown_mode`, `probe.sudo_config`, `probe.ssh_keys`, `probe.host_metrics`, `probe.scheduled_jobs`, `probe.logins`. **Full check (at most every 6 h, on main-window open, and on "Check now").** The collectors are called per `SectionKey` from a fixed list in `watch/probes.rs`, not through `collect_system_state` (which has no skip list and stays a main-window command). The list omits `LoginItems` unless `check_capabilities` reports Automation `granted`, and omits `Browsers` unless Full Disk Access is granted, so no system prompt ever appears from the background. Rules diff as in v0.3.

**File-content reads, declared.** The standing rule allows file contents only under the narrow exceptions in SECURITY-MODEL "Files the collectors open". The watch adds exactly two, both metadata-first and both Rust-chosen: (a) `codesign --verify --strict -- <path>` on the binary a new launch item names, where `codesign` hashes the file and the app's own code reads no bytes; (b) nothing else. `/etc/hosts`, `/etc/pam.d/sudo`, `/etc/pam.d/sudo_local`, `~/.ssh/authorized_keys` and `/etc/ssh/sshd_config` are `stat` only (size, mode, mtime); their contents are never opened by the watch. `crontab -l`, `atq` and `last -n 50` are binaries, not file reads, and their output is reduced to counts in the probe.

**Binding the codesign target.** The plist's `Program` or `ProgramArguments[0]` is taken as a candidate only if it starts with `/`, canonicalises to itself, is a regular file, and is not under `~/Desktop`, `~/Documents`, `~/Downloads`, iCloud Drive (`~/Library/Mobile Documents`), `/Volumes`, `/Network` or a network mount (`statfs` with `MNT_LOCAL` clear), so no Files and Folders prompt and no background network read can rise from it. The folder rules run on the path's short spelling: `realpath` leaves the `/System/Volumes/Data` firmlink and the `/private` symlink as written, so both are stripped before the comparison (`signals::normalise`), and the temp and hidden class (row 1) uses the same spelling. Anything else, including a bare name, an all-digit value (which `codesign` would treat as a pid; verified on this Mac) or a value starting with `-`, is recorded as `unbound` and counts as `unsigned`. The `--` separator is used (exit 0 on this Mac). Cap of 10 per cycle, 5 s timeout each.

**Cannot be done without Full Disk Access or root, and is said so in the doc and in the window.** Safari extension state and Chrome/Firefox extensions (FDA); the Background Task Management database and `sfltool dumpbtm` (root); other users' crontabs (root); `profiles list -all` and system-scope profiles (root); `/etc/sudoers` contents (root); `eslogger` and any EndpointSecurity client (root, FDA and an entitlement the project does not have); `pfctl` (root); process-to-socket mapping on ad-hoc builds (Developer ID signing fixes it); the unified log on a standard account (admin group). TCC.db is never read. These appear in the window's "I couldn't check N areas" line with the same reasons the v0.2 permission card uses.

**Noise suppression.** A signal whose change lands within 10 minutes of a change in `sig.persistence_set` that `codesign` reports as valid, or within 10 minutes of a Talos fix, is held for one more cycle before it counts. Unchanged signals are not reported. The raw process set (`ps`) is not a signal because every app launch changes it; only the path-class counters from the persistence probe are kept.

## 3. The bounded agent

**Shape.** Rust is the agent; the model is a one-shot judge per cycle. One cycle is one timer tick. Nothing in a cycle can run a tool loop, because the model's answer is a list of ids that Rust acts on after the call, and the next model call is the next cycle. The whole cycle runs in Rust, so it does not depend on any webview being alive.

**Types** (`apps/desktop/src-tauri/src/watch/types.rs`, mirrored in `packages/core/src/ports/watch-port.ts` with the same parity test as the explainer schemas).

There is no field of type `string` outside closed unions except the three capped sentences and the regex-validated OS version, so there is nowhere for machine text to go. `WatchDetails` (section 8) is a separate type, returned by a separate command, and is never an argument to any adapter; a test proves it (section 9).

**Floor and ceiling: code judges, the model explains.** `rate_watch(context)` is pure. The first cycle after enabling (no baseline) writes the baseline and returns calm with no changes; `first_seen` counts only against an existing baseline.

Floor is `act_now` when:
- `sig.sip`, `sig.gatekeeper`, `sig.xprotect_present` or `sig.xprotect_scans_enabled` went on-to-off without a Talos fix in the same window, or `sig.xprotect_version` went down (stand-alone: these need Recovery or root);
- `sig.hidden_user_count` rose (stand-alone: no Settings pane does this);
- a gated flip (`sig.firewall` off, `sig.remote_access_on`, `sig.guest_share`, `sig.autologin`, `sig.admin_count` up, `sig.backup_auto` off) was answered "No, I didn't";
- or two of {`sig.persistence_new`, `sig.persistence_unsigned`, `sig.persistence_in_temp_or_hidden`, `sig.listener_new_ports`, `sig.dns_manual`, `sig.pac_url_set`, `sig.profiles_count` up, `sig.sysext_count` up, `sig.authorized_keys_changed`, `sig.cron_lines` up, any gated flip} changed within 24 h.

Floor is `keep_an_eye` when any high or medium signal changed in 24 h (a lone unsigned or dot-folder item lands here), any gated flip is unanswered, any rule appeared, or any signal is `unavailable` that was `fresh` before. Calm otherwise. Ceiling is `act_now` only when at least one high signal has `change != same`, is not acknowledged and is not gated; `keep_an_eye` when any unacknowledged change exists; calm otherwise. The shown rating is `max(floor, min(verdict.rating, ceiling))`. The model cannot invent an emergency from calm data and cannot talk a real one down. Unavailable is never calm. "Not now" on any fishy screen caps the shown rating at `keep_an_eye` for that item for 14 days (section 5).

**Loop.** Every `watch.everyMinutes` (default 60; options 15, 60, 240) while the Mac is awake, plus once on wake when more than an interval has passed. Steps: (1) check the in-flight counter in `AppState` (a new `AtomicUsize` incremented by `collect_system_state` and `collect_section`, which covers scans and watcher polls) and `PlanStore::is_busy()` (fix or batch); skip the tick if either is set; (2) the cheap sweep within a 20 s wall budget; (3) `to_watch_context(previous_baseline, fresh, memory, now)`; (4) `rate_watch`; (5) at most one model call, only when AI is on, the provider is `available`, and (something changed since the last call, or floor >= `keep_an_eye`, or 24 h passed); one retry at most, as DESIGN-AI section 8 allows; (6) `validate_watch_verdict`; (7) run at most three model-chosen probes from `MODEL_PROBES`, each honouring its own minimum interval, within the same 60 s cycle budget; their results feed the next cycle; (8) persist the baseline and the rating; (9) update the icon and, on a transition into `act_now`, the notification policy (section 5). Hysteresis: the rating rises at once and falls only after two consecutive calm cycles.

**Validator.** `validate_watch_verdict(raw, context)`: rating in the enum, then clamped; every id in the matching list of the document the call was built from; duplicates rejected; over cap rejected. An action is dropped (the verdict kept) when its playbook row's `floor` is above the clamped rating, or when none of its `triggers` has `change != same` in this context. Each of the three strings is dropped (the verdict kept, the clamp untouched) when it fails `containsCommandText`, or matches a path-like token (`[~/][A-Za-z0-9._-]`), a port-like token (`:[0-9]{2,5}\b`), or any of the words pid, process, kill, delete, remove, rm, unload. The model sentence is shown only on Advise rows, never on a sheet whose button runs a catalogue entry, so a model sentence can never read as the instruction above a fix button. `ratingReason` and `reason` are never persisted. A rejected whole verdict is `rejected_output` and the fixed rules stand.

**Limits.** Daily cap of 24 model calls (one counter, whichever provider answers); a hard stop on `limit_reached` until `until`. Prompt budgets: on-device 7000 chars (`ON_DEVICE_LIMITS`), changed signals first, unchanged rules dropped first; remote 12 000 chars (a new `WATCH_LIMITS`); output 600 tokens on-device, 1200 remote. Stop conditions: AI off, provider not available, the cap, the cycle budget, the in-flight counter, `PlanStore::is_busy()`, a guided step on screen, "Pause for an hour", the watch switch off, `watch.onBattery` is false and the Mac is on battery (default: tick on battery too, because the sweep is 0.6 s; the full check waits for mains).

**Providers, all driven from Rust.** The watch task is built by Rust's own loop; a webview request naming `watch` is refused by `ai_generate` and `claude_generate` with `invalid_input`. On this Mac: `Task::Watch` in `ai/protocol.rs`, a `@Generable WatchVerdict` in the Swift helper, the `watch` prompt builder with the existing trimming loop, one `LanguageModelSession` per cycle. ChatGPT: the request body is built in Rust (`ai/chatgpt_watch.rs`, a port of `responsesRequestBody("watch", ...)` with `store: false` and the strict schema) and sent with `ureq` to `https://api.openai.com/v1/responses` using the token Rust already holds in the Keychain; a fixture parity test pins the Rust body to the TypeScript builder's output. Claude Code: `claudePromptFor(turns)` over stdin, `schemas::for_task(Task::Watch)`, the same locked-down argv (`--tools "" --max-turns 2 --permission-prompts none`, fresh `/private/tmp` cwd, `codesign` before every spawn). A Claude Code spawn costs a few seconds per cycle; fine at 60 min. The instructions add one block to the frozen system prompt: "You rate, and choose probes and actions by id. You cannot run anything. The ids are the only vocabulary." The badge on every model sentence: "Written by ChatGPT. Not verified." as in DESIGN-AI.

**AI off, not connected, not offered, limit reached.** `rate_watch` alone gives the rating; actions come from `triggers: &'static [SignalId]` on each playbook row; the surfaces are identical; the badge reads "Decided by the app itself". The app is complete with AI off.

**Canary.** `packages/core/test/helpers/canary-state.ts` gains `CANARY_NEXT` (every injected string changed; a second launch agent with an injected label under an injected temp path; a new share; one more admin). `toWatchContext(evaluate(CANARY), evaluate(CANARY_NEXT), probeResults, memory, now)` must serialise to JSON containing neither `INJECT` nor `IGNORE`, every string in a closed union or under `SAFE_STRING_PATTERN`, and digest-kind signals carrying only the `Change` enum. `remote.test.ts` adds `watch` to the task loop so both adapter bodies are checked, and asserts no `WatchDetails` field name (`plistPath`, `label`, `programPath`, `port`, `processName`) appears in any body. Rust: a `ProbeResult` built from a listing whose label and program are "IGNORE PREVIOUS INSTRUCTIONS" serialises to a signal set with no such substring; the request body builders accept only `WatchContext` by type; `validate_watch_verdict` rejects an unknown action, probe or signal id with `rejected_output`, rejects `probe.persistence_signatures` and `probe.ssh_keys` as model choices, and an `act_now` verdict against a calm ceiling is shown as calm. The `println!`/`eprintln!`/`dbg!` grep test covers `watch/`, `tray.rs` and the single-instance callback.

## 5. Menu bar experience

**Icon.** One tray item built in Rust at setup (`TrayIconBuilder::with_id("watch").icon(include_image!("./icons/tray-calm.png")).icon_as_template(true).tooltip(...).menu(&menu).show_menu_on_left_click(false)`). App commands are ACL-gated through an app manifest built from `src-tauri/commands.txt`; main's capability lists listen, unlisten, start-dragging and one `allow-` entry per command; the watch window's capability lists listen, unlisten and the four watch commands; no webview can emit events, build menus or touch the tray, which is built and changed from Rust only. Template images, black plus alpha, 36 x 36 px raster at 2x for an 18 pt item, so macOS draws it in the menu bar's own ink in light, dark and selected states; the app never chooses a colour and the icon is never red. Three states: calm, the kit's `check-up.svg` (three rings); something to look at, the same rings with a 4 pt filled dot at lower right; act now, an octagon with a bar, drawn in the kit's 1.5 px stroke as a new tray-only raster. The octagon is used because `apps/desktop/src/app/icons.ts` keeps the kit's triangle for high severity and lucide's `OctagonAlert` for critical, and "act now" is the critical level; DESIGN-MINERAL section 4 gets a line recording the tray raster as the one glyph drawn outside the kit's SVG set, and why (template raster, one stroke family). No flashing, no animation, no text beside the icon (`title` stays empty). Tooltip carries the state and the time: "Talos Labs: nothing changed since the last check. Checked 12 minutes ago." / "Talos Labs: one thing to look at." / "Talos Labs: act now." When the watch is off the item is removed, not greyed.

**Clicks.** Left click toggles the window under the icon. `TrayIconEvent::Click` carries `rect: tauri::Rect { position, size }` in physical pixels with a top-left origin; the placement is `let scale = monitor.scale_factor(); let y = rect.position.to_logical(scale).y + rect.size.to_logical(scale).height;` with x centred on the icon, the monitor found with `app.monitor_from_point`, and the result clamped to `work_area()`; no positioner plugin, no new permission. Right click shows a native menu: Open Talos Labs · Check now · Pause for an hour · Turn the watch off · Quit Talos Labs. The window hides on `WindowEvent::Focused(false)`; `show()` is followed by `set_focus()` so blur fires; a `Focused(false)` within 150 ms of a tray click is ignored so a click on the icon while the window is open closes it rather than reopening it.

**Window anatomy (Mineral).** A second Tauri window labelled `watch`: 320 px wide, height to content (max 360), `url: "watch.html"`, `decorations: false`, `visible: false`, `alwaysOnTop: true`, `visibleOnAllWorkspaces: true`, `resizable: false`, `transparent: false`, `shadow: true`, `acceptFirstMouse: true`, `skipTaskbar: true`; its own capability file, `capabilities/watch.json`. Decided on purpose: the window is not a guided step. One primary holds; the two footer links are allowed because the window is a status surface, like the title strip, not a step. First-run state (before the first tick): "I'll check your settings on a timer and tell you when something changed." with the link "Start me when you log in" (opens Settings on the Watch section).

**After "Not now".** "Not now" on any fishy screen (sections 6) writes `actionNotNow[actionId]` for 14 days and drops that item to "something to look at": the icon shows the dot, the window keeps the headline with "Show me", and the tooltip reads "Talos Labs: one thing to look at." No act-now state survives a "Not now". "This is fine, I know it" and "Yes, that was me" clear the item altogether by re-baselining the signal.

**When it speaks.** A notification is sent only on a transition into act now, once per item id, never repeated for the same item, and never more than one in any 24 h unless a different act-now item appears. A gated flip never notifies until it has been answered "No, I didn't" or corroborated. "Something to look at" never notifies; the dot is the whole signal. No sound. The plugin sets no interruption level on macOS; Focus modes apply as macOS decides. Title "Talos Labs", body one fixed sentence from the headline set in section 6 plus "Open me to see what experts suggest." No program name, port or path in a notification, ever. Clicking opens the main window on the noticed screen (the plugin reports clicks on desktop). Nothing else may notify: not the paywall, not the AI row, not a snoozed step, not "since last time", not a calm result. Snoozes carry over from guided memory.

**Permission.** macOS's own "allow notifications" alert is requested only in the foreground: from the "Tell me when something needs doing now" switch in Settings and from the Welcome sentence's disclosure, never from a tick. If permission is absent at an act-now transition, the window shows the change and no prompt appears. The plugin's `permission_state()` reports Granted on desktop whatever the person chose, so the app cannot tell when it has been silenced and does not pretend to.

**Build truth for notifications.** `tauri-plugin-notification` 2.7.0's desktop path goes through notify-rust and mac-notification-sys and the deprecated `NSUserNotificationCenter` API. In a dev build it sets the application to `com.apple.Terminal`, so `pnpm desktop` builds do show banners, under Terminal's name; a bundled build uses `si.taloslabs.desktop`. Delivery through that deprecated API on macOS 26 and 27 is unverified and sits in the section 9 real-Mac list; if it fails, the fallback is in-window only and this paragraph is updated.

**Settings.** A new "Watch" section above "Check-up" in `apps/desktop/src/screens/Settings.tsx`, grouped like `CheckUpSection`:

1. Switch "Keep an eye on my Mac from the menu bar" (`watch.enabled`, default true). Section sentence: "With this off, Talos Labs only checks when you open it."
2. Switch "Start when I log in" (`watch.startAtLogin`, default false). Description: "Adds Talos Labs under Allow in the Background in System Settings. You can switch it off there too."
3. Segmented "How often": Every 15 minutes · Every hour · Every 4 hours (`watch.everyMinutes`, default 60).
4. Switch "Tell me when something needs doing now" (`watch.notify`, default true; turning it on requests the macOS permission). Description: "Only for things that need doing now. Never about the full version or AI."
5. The not-antivirus sentence from section 1.

**Start at login.** `tauri-plugin-autostart` 2.7.0 with `MacosLauncher::LaunchAgent` and the argument `--watch`, which `main.rs` reads to open only the tray and no main window while the watch is on; with the watch off it is a normal launch (`lib.rs::start_hidden`), and turning the watch off removes the agent (note 44). The plugin writes `current_exe().canonicalize()` into a LaunchAgent labelled with `package_info().name`, "Talos Labs" (from `productName`); it lands under "Allow in the Background", labelled "unidentified developer" on unsigned builds, and the Settings description says where it lives. SMAppService would be the better route but no Tauri plugin wraps it; out of scope for the first cut. The app's own agent is a persistence item: rule 023 lists it like any other under the label "Talos Labs" (no allow-list, so a look-alike cannot hide behind the name, and the test expects that row), and the watch baseline excludes exactly one entry whose canonicalised program path equals `std::env::current_exe()?.canonicalize()?`, so switching the setting on does not trip the watch. `tauri-plugin-single-instance` 2.5.4 is added so a login start plus a Finder launch gives one process and one icon; its callback receives the second launch's argv and cwd, which are machine text, and discards both: it only shows and focuses the main window. The callback is covered by the no-logging grep test.

**Running without the main window.** `app.set_activation_policy(ActivationPolicy::Accessory)` when only the tray is shown; `Regular` plus `show()` and `set_focus()` when the main window opens; on the main window's `CloseRequested` with the watch on, `prevent_close`, `hide`, back to `Accessory`. `.build(ctx)?.run(|app, event| ...)` handles `RunEvent::ExitRequested { code: None, api, .. }` with `api.prevent_exit()` while the watch is on, and `RunEvent::Reopen` as the Dock click. `PredefinedMenuItem::quit` never raises `ExitRequested` at all (it terminates the process directly), so a custom "Quit Talos Labs" item (Cmd+Q, id `talos-quit` shared with the tray) that calls `app.exit(0)` is mandatory in `menu.rs`, and the tray's Quit does the same; the run callback swallows only `ExitRequested { code: None }`, which is the last-window-closed case, and lets `app.exit(0)` through. Known gotcha to verify in the first prototype: under `Accessory` the app menu is gone, so Cmd+C/V in the tray window may not work; if so, keep `Regular` with `set_dock_visibility(false)`.

**Scheduling and battery.** `tokio::time::interval` with `MissedTickBehavior::Skip`. Timers pause in sleep because std `Instant` uses `CLOCK_UPTIME_RAW`; a wall-clock gap larger than the interval at a tick, or `NSWorkspaceDidWakeNotification` (observed from the main thread through `objc2-app-kit`), triggers one tick on wake. The cheap sweep runs on battery (0.6 s); the full check waits for mains unless the person presses "Check now". Nothing runs while the in-flight counter or `PlanStore::is_busy()` is set, or within 60 s of a manual check (the DESIGN-V03 guard). XProtect Remediator itself runs about daily, so hourly is already more often than Apple.

## 7. Storage and privacy

**Rust: `<app data>/watch.json`, mode 0600.** Every field of `Baseline` (`watch/baseline.rs`, camelCase on disk): `{ version: 1, key: base64 (32 random bytes), baselines: Record<SignalId, { kind: "bool" | "count" | "version" | "digest", value, members?: keyed digest[], seenAt: ISO, observed?: { value, members?, changedAt: ISO }, freshness }>, rules: { ruleId, status }[] (the last report's snapshot, note 1), recent: last 50 { signalId, change, at }, lastRating, ratingSince: ISO | null, calmStreak: number, lastModelCallAt: ISO | null, callsToday: { date, count }, closeWatchUntil: ISO | null, gates: Record<SignalId, ISO> (open "Did you just change this?" questions), gateAnswers: Record<SignalId, "not_mine"> (a "Yes, that was me" re-baselines instead), snoozed: Record<SignalId, ISO> (note 4), notified: Record<SignalId, ISO> (the once-per-item notification ledger), acknowledgeCount: Record<SignalId, number> (the three-strikes mute, note 35), lastFullCheckAt: ISO | null, cycleIndex: number, lastFixAt: ISO | null and lastSignedChangeAt: ISO | null (the two noise holds, cleared after one cycle), lastChangeAt: ISO | null }`. Ids, dates, counts, closed words and keyed digests only; no machine text. The digests are HMAC-SHA-256 over sorted machine-text sets (plist listings, labels, ports, resolver lists) under the per-install key. They are the first values derived from machine text that the app persists. A plain hash of a low-entropy set (a port list, a short list of names) could be matched against a dictionary, so the digest is keyed: it is not reversible without the key, and the key lives only in this file. Digests are never serialised into any document, never sent anywhere, and deleted with the file when the watch is turned off. The doc says this plainly and so must `SECURITY-MODEL.md`.

**Webview: `localStorage["talos.watch"]`**, parsed field by field like `parseGuidedMemory`: `{ version: 1, snoozedSignals: Record<SignalId, ISO>, normalForMe: Record<SignalId, ISO>, acknowledgeCount: Record<SignalId, number>, actionNotNow: Record<ActionId, ISO>, fishyRanAt: ISO | null, notifiedItems: Record<SignalId, ISO> }`. Ids and dates only. "This is fine, I know it" three times on the same signal mutes it until a full check sees a new change (mirrors `laterCount`). "Not now" on an action is honoured 14 days like `aiAskedAt`.

**Settings:** `watch.enabled`, `watch.startAtLogin`, `watch.everyMinutes`, `watch.notify` in `AppSettings`.

**What changes in `docs/SECURITY-MODEL.md`.**
- "What the app never does": the wording in the decisions above.
- Line 138, "The model has no tools and no way to call back into the app", becomes: "The model has no tools. In the watch task it may name up to three probe ids from a closed, compiled-in table of re-reads that touch listings, `stat`, `defaults read`, fixed-argument binaries, and the launchd plists under the existing exception; Rust runs them after the call, their result feeds the next cycle, and the two Rust-only probes (`probe.persistence_signatures`, which runs `codesign` on a binary, and `probe.ssh_keys`, which is `stat` only) are never model-choosable. ## 10. Out of scope

Antivirus or EDR of any kind; EndpointSecurity; file scanning; network traffic inspection; the unified log; `periodic`; system crontabs, BTM, system-scope profiles, sudoers contents, pfctl (root); Safari extension state (FDA); SMAppService; a non-activating NSPanel or NSPopover and Tauri's `macos-private-api` feature (private API, so the watch window is opaque with square corners); killing a process by name or pid; deleting a plist or an account from the app; forensic imaging; a US or any national reporting link; auto-containment without a confirmation; notifications for anything but a transition into act now; a per-user watch across accounts; Windows and Linux; localisation beyond British English; the model deciding what to fix (the plan stays a pure function); payment, the licence year, telemetry.

A change that clears on its own, or is accepted after a day, takes its gate, answer, snooze and notification-ledger entry with it (and its listing siblings' unless they still show a change), so a later change on the same signal is asked about and may notify again. A notification is decided on the raw rating (a hysteresis hold never notifies) and a hold never shows act now without an item that is neither gated nor snoozed; it shows "something to look at" instead and the streak carries on. `hasStartupEntry` and `isListener` on an item are bound from the Details rows of the item's listing, not from its kind, so the Stop screen appears only when a plist can be bound. Commands never wait on a running cycle: the baseline sits under its own short lock, a command's edit lands on it at once and is replayed onto the cycle's copy before that copy is saved (`WatchStore::apply_edit`, `finish_cycle`); the four commands that write it run off the main thread. "Check now" lifts "Pause for an hour", and a check asked for while a scan or fix runs shows "Checking now" and runs when it ends. The watch's model call skips an engine the person is using and yields the slot (its call is cancelled) when the person's request arrives mid-cycle. Token refreshes are serialised behind one lock so the webview and the cycle never send the same refresh token twice. The watch window is sized from Rust per state: 170 px first run, 150 calm, 280 look, 360 act (`tray::window_height`); the QA harness captures each state at that height and warns when the content is taller, which is how the earlier 160 and 240 were found to clip the first-run and look windows by 3 and 12 px.
36. Rows 7, 9 and 14 keep counts only; no digest of admin names, bundle ids or cron lines is made, so a swap of one name for another at the same count is not seen. The digests in `watch.json` are the launch listing, the listener set, the resolver list and the four `stat` keys. The proxy state (row 10) is read from `networksetup` only; `scutil --proxy` does not run.
37. The tooltip has five forms, not the three of section 5: calm with or without the "Checked ..." suffix (the window's rounding, so none before the first check), "Talos Labs: something to look at." when the rating holds with no item (a rule appeared, a good flip, a hysteresis hold), "Talos Labs: one thing to look at.", "Talos Labs: {n} things to look at.", and "Talos Labs: act now." (`tray::tooltip`, pinned in tray.rs tests).
38. One listing change is one item: `top_items` (and `topItems` in core) keeps the highest-points member of each `signals::siblings` group, ties by `SignalId` order, so a new unsigned agent in a temp folder (four changed signals) is "one thing to look at", not four. The listing digests `sig.persistence_set` and `sig.listener_set` keep their kind but make an item only when a counter from the same listing rose; a removed launch item or a closed listener is a medium change (the floor still says look) with no "new program" headline. A "Not now" on the item snoozes the listing's siblings, and `conclude` sets every snoozed signal aside, not only the items, when it decides whether act now survives.
39. The fix hold is bounded: a change within ten minutes of a Talos fix is held; a change first seen on the tick after a fix is held too, since its time is only known to the tick and `last_fix_at` is cleared every cycle, unless the signal is in `STAND_ALONE_SIGNALS`, which no Talos fix moves and which act at once. The main window's open (`tray::open_main_plain`: tray menu, Dock reopen, second instance, notification tap, the small window's links) asks the loop for a full check through `WatchStore::request_full_check`; the 60 s manual guard, a pause and the mains-only rule still decide when it runs.
40. The end screen never reads calm above the act-now card: its title is `WATCH.act` ("Act now") and the sentence under it is the item's FISHY headline with a stop, in place of "Nothing needs fixing." and "I'll keep checking from the menu bar."; the tick mark is withheld. Screen 1 carries the evidence sentence inside Details (`.fishy-evidence`), next to the file and program lines it is about, since its body already holds the three spec sentences. "Not now" on the disconnect screen declines the row that screen carried: `act.disconnect_network` on a Wi-Fi Mac, `act.block_incoming` on a wired one; `stagesFor` takes `wired` and `useFishy` recomputes the stages once Details arrives, keeping the screen on show in place.
41. The SECURITY-MODEL bullet under "What the app never does" names the exceptions in place of the "two declared exceptions" wording given above: "never reads file contents beyond the exceptions declared under "Files the collectors open" (the `codesign` hash of a new launch item's program, and the launchd plists under the existing exception)". The reason is note 21: `probe.persistence` reads plist bytes under the existing exception, so section 2's "exactly two" is one new exception plus the launchd one, and the bullet says which.
42. With the watch on, closing the main window hides it (note 33), so a reopen no longer remounts the webview and the mount-time launch check-up of DESIGN-V03 ("Check my Mac when I open Talos Labs") would never fire again. Every open of the main window (`tray::show_main`, behind `open_main` and `open_main_plain`) reads `is_visible()` before `show()` and, when the window was hidden, emits `main:shown { screen }` after `watch:open`, `home` for a plain open. `App.tsx` runs the launch check-up on `home` only, under the same conditions as at mount (onboarded, `guided.autoScan`, `guided.home`, the 60 s `claimLaunchScan` guard); `noticed` and `settings_watch` land the person on another screen and run no scan. A `--watch` login launch hides the window but still boots the webview, so `WatchState.hiddenLaunch` is true from `lib.rs` setup until the first open (`watch::mark_hidden_launch`, `watch::on_main_open`, published through `watch:state` and `watch_status`); `App.tsx` reads it from `status()` at mount and holds the launch check-up for `main:shown`. So a login launch runs no `collect_all`, writes no report and raises no Automation consent dialog with no window behind it. The demo port is never hidden and its `onShown` never fires.
43. Two loop fixes. `run_once` reads `full_check_requested` before the `manual ||` chain (`cycle::full_check_plan`), so "Check now" consumes the request a window open left and the next tick does not run the Automation- and FDA-gated collectors a second time; a request the mains-only rule defers is re-armed, not dropped. The timer loop skips a wake only when it was a reconfigure with nothing pending (`watch::skip_wake`): `Notify` stores one permit, so a check-now, a refresh or a window open that coalesced with `set_interval` or `close_watch` while a cycle ran used to wait a whole interval with "Checking now" never shown.
44. `watch_set_enabled(false)` also disables the login item: Rust `watch::set_enabled` calls `autolaunch().disable()`, so the LaunchAgent under `~/Library/LaunchAgents` goes with the watch and no hidden process starts at login for a watch that is off; `useWatch.setEnabled` mirrors it by writing `watch.startAtLogin: false`. A `--watch` launch with the watch off is a normal launch that shows the main window (`lib.rs::start_hidden`). SECURITY-MODEL names both removers of the agent.
45. Turning the watch off with the main window hidden behind the tray (closed with the watch on, or a `--watch` login launch) used to leave a process with no window, no Dock icon, no tray item and no way to quit: `ExitRequested` never fires for a hidden window. `watch::set_enabled(false)` now ends with `tray::after_watch_off`: `tray::turn_off_follow_up(has_main, main_hidden)` says `Show` (through `open_main_plain`, so the Dock icon and the window return), `Exit` when there is no main window at all, or `Nothing` when the window is on screen or minimised. Pinned in tray.rs. The hidden state is a flag, `TrayState.main_hidden`, set by `tray::hide_main` (the close with the watch on, and the `--watch` setup path in lib.rs, which now calls `hide_main`) and cleared by `show_main`; it is no longer read from `is_visible()`, which also answers no for a minimised window, so Cmd+M followed by "Open Talos Labs" no longer emits `main:shown` and no longer runs the launch check-up for a window that was never closed. `show_main` also calls `unminimize()` on a minimised window before `show()`.
46. A refresh after "This is fine, I know it", a gate answer or "Not now" runs through "Pause for an hour" (`cycle::pause_holds(paused, refresh)`); the pause itself stays, so the next timer tick still waits. Before, `run_once` dropped the refresh while paused and the cleared act-now card and the old tray icon stayed for up to an hour plus one interval, against note 32. The test is on the pure pieces (`pause_holds`, then `Edit::Acknowledge` plus `refresh` on a paused baseline, items empty and rating calm): `run_once` needs an `AppHandle`, which the Rust tests do not build, and it would run the real sweep probes on the test Mac.
47. Run folders under `/private/tmp` are swept, not only dropped. `RunDir::create` names a folder `talos-claude-` plus sixteen lowercase hex digits and registers it in a process-wide list; `Drop` removes both. `claude_code::sweep_run_dirs(root, now)` removes entries with that exact name shape that are real directories (no symlink), owned by the current uid, older than `RUN_DIR_MAX_AGE` (15 minutes, past the sign-in's 600 s `CONNECT_DEADLINE` and the 180 s `WHOLE_TIMEOUT`) and not in the live list. lib.rs runs it on a thread at setup and again on `RunEvent::Exit`, where the live list is removed first, since `app.exit(0)` from Cmd+Q or the tray's Quit ends the process without unwinding the thread that holds a run dir. A force quit or a crash leaves the folder for the next launch's sweep. Ten such folders were found on the development Mac before this change.
